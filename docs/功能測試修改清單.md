# 字力測驗 功能測試後修改清單

> 來源：實際使用兩週 + Claude for Chrome 全流程測試（桌面版 + 手機版）回饋整理
> 優先順序：由上到下

---

## 1. 【優先】手機版導覽列消失、無替代入口

**問題**：
手機寬度（約 <820px）下，頂部導覽列目前把「背誦」「測驗」「設定」等連結直接隱藏，沒有漢堡選單或其他替代入口。這是從最早 HTML 風格提案就帶著的設計遺漏：

```css
@media (max-width:820px){ .nav-links{ display:none; } }
```

**影響**：
手機使用者一旦離開首頁進入背誦/測驗流程，若想切換功能（例如背誦切測驗、或去帳號設定），沒有直接路徑可點，只能點麵包屑繞回單字本列表再重新點選。

**修改方向**：
- 手機寬度下改顯示漢堡選單 icon（≡），點擊展開下拉或側滑選單
- 選單內容：桌機版原有導覽項目 ＋ 額外加上「回單字本列表」「帳號設定」「登出」（桌機版這些可能藏在頭像 hover 選單，手機版建議攤平放進漢堡選單，減少多層點擊）
- 所有內部頁面（單字本內、背誦頁、測驗頁、設定頁）需套用**同一份**導覽 component，不要各自處理，避免各頁面行為不一致

---

## 2. 單字池數字「先顯示 0 再更新」的延遲

**問題**：
背誦頁與測驗設定頁，選定單字本/標籤篩選後，「符合的單字池」數字會有約 1 秒非同步延遲，先顯示 0 才更新成正確字數。這段期間開始按鈕呈灰色不可點擊。

**影響**：
容易讓使用者誤以為單字本是空的，屬於體驗上會造成誤解的問題，非單純美觀問題。

**修改方向**：
- 避免直接渲染預設值 0，改用 loading 狀態（骨架屏、spinner，或至少顯示「計算中...」文字）
- 若技術上可行，改成同步計算/即時計算，省去非同步等待

---

## 3. 新增單字「儲存中...」等待回饋不夠明確

**問題**：
新增單字表單送出後，按鈕僅文字變灰、無其他視覺提示，等待約 2-3 秒才寫入成功。

**影響**：
容易讓使用者誤以為畫面卡住。

**修改方向**：
- 按鈕加上 loading icon（轉圈動畫）或明確的「儲存中」視覺狀態
- 可考慮樂觀更新（optimistic update）：先在畫面上顯示新單字，背景確認寫入成功後再定案，失敗則回滾並提示錯誤

---

## 不需修改，僅供留意

- **是非/選擇題答題後無立即對錯反饋**：這是技術文件中原本定案的設計（避免影響作答節奏，結果頁已有完整正確率與答錯清單），確認為刻意設計，不需更動
- **填空題 Levenshtein 紅字標記**：測試中確認邏輯正確落地（例如多餘字母能精準標紅），做得好，維持現狀即可
- **Excel 匯入**：Kenter 已自行實測，格式與上限提示皆正常，不需再處理
- **其餘 RWD 細節**（單字本卡片單欄化、測驗設定題型卡片直向排列、modal 置中、結果頁圖表在窄螢幕下完整呈現等）：測試確認正常，維持現有做法
