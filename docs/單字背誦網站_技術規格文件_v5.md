# 單字背誦網站 技術規格文件(v5)

> 本文件聚焦技術實作細節(資料庫設計、業務邏輯、演算法規則),對應「單字背誦網站_營運文件.md」中定案的業務規則。
> 前端頁面與程式碼實作交由開發工具(Claude Code)處理,本文件僅提供架構與邏輯依據。

## 版本更新說明(v5,取代 v4)

> v5 對應產品定位調整:由「檢定考試單字工具」轉為「**多語言(英/日/韓)自學者的單字成長系統**」,加入遊戲化與成長感。本版為第一階段(成長與熟練度地基),小遊戲、發音、AI 抽字、社群功能列為後續階段(見第十、十一節)。

- **新增「每日任務」作為主要學習路徑**:學習範圍改由系統依熟練度指派,使用者僅設定「學哪些語言」與「每日量」,不手動選範圍(取代 v4「測驗範圍完全由使用者手動選擇」的定案)。手動篩選保留為「自由練習」與卡牌模式(詳見第八節)。
- **新增熟練度與間隔複習機制**:新增 `word_progress` 表,以階段(stage)+ 間隔天數排程複習;「已掌握」定義為在不同日期連續答對達門檻,而非存了多少字(詳見第八節)。
- **單字本新增語言欄位**:`wordbooks.language`(`en` / `ja` / `ko`),作為每日任務分語言產生與成長面板分語言統計的依據(見第三節 1.)。
- **新增成長系統**:成長面板(分語言掌握數與等級)、連續天數、成就(詳見第九節)。
- **帳號暫停時成長資料凍結**:暫停期間成就與連續天數凍結而非歸零,付費恢復後接續;資料清除時一併刪除(詳見第九節 4.)。
- **填空題方向定案為「看中文、拼外文」**:顯示 `answer`(中文),使用者輸入外文 `term`;使用者平時預設使用外語輸入法,不需在中文與外語輸入法間切換,且避免中文譯義措辭不一的誤判(見第五節 8.)。
- 其餘 v4 邏輯(狀態機、500 字上限、早鳥、改善建議、LINE Login、Excel 匯入)不變。

## 一、帳號與訂閱狀態機

### 1. 狀態定義

| 狀態 | 說明 | 觸發者 |
|---|---|---|
| `trial` | 試用中,30 天,單字上限 500 | 系統(註冊時自動設定) |
| `active` | 付費中,正常扣款,無單字上限 | 系統(扣款成功) |
| `payment_failed` | 扣款失敗,進入 10 天寬限期,功能仍可正常使用 | 系統(扣款失敗) |
| `suspended` | 已暫停,全部功能鎖定(僅可匯出資料) | 系統(試用期滿未付費 / 寬限期滿未扣款成功) |
| `cancelled` | 已取消/刪除,資料清空 | 使用者主動操作,或系統於保留期滿後自動清除 |

### 2. 狀態轉換邏輯

```
trial ──(30天內完成付款)──> active
trial ──(30天到期未付款)──> suspended
trial ──(使用者主動刪除帳號)──> cancelled

active ──(每月扣款成功)──> active(更新 next_billing_at)
active ──(扣款失敗)──> payment_failed
active ──(使用者點「取消訂閱」,auto_renew=false)──> active(維持可用,不再續扣)
active(auto_renew=false) ──(到達 next_billing_at,略過扣款)──> suspended
active ──(使用者主動刪除帳號,不論 auto_renew 為何)──> cancelled

payment_failed ──(10天內補款成功)──> active
payment_failed ──(10天寬限期滿仍失敗)──> suspended
payment_failed ──(使用者主動刪除帳號)──> cancelled

suspended ──(使用者完成付款)──> active
suspended ──(使用者主動刪除帳號)──> cancelled
suspended ──(3個月保留期滿,資料清除排程執行)──> cancelled

cancelled ──(使用者以同一LINE帳號再次登入,視為全新帳號)──> trial
```

> 保留期滿觸發的清除視同帳號取消:資料清除完成後 `status` 一律轉為 `cancelled`(不維持在 `suspended`),避免系統中出現「資料已空但狀態仍是暫停」的曖昧狀態。
>
> `cancelled` 並非真正的終態:使用者的 `line_user_id` 資料列保留,若日後以同一 LINE 帳號再次登入,系統視為全新帳號,重新進入 `trial` 並給予完整 30 天試用期(見第二節 3.1)。
>
> **「取消訂閱」與「刪除帳號」是兩個獨立操作,定案如下:**
> - **取消訂閱**(僅限 `active`):使用者點擊後只設定 `auto_renew = false`,`status` 維持 `active`,功能持續可用至 `next_billing_at` 當天;排程於 `next_billing_at` 檢查到 `auto_renew = false` 時,略過扣款、直接將 `status` 轉為 `suspended`(不進入 `payment_failed`,因為這不是扣款失敗,而是使用者主動選擇不續訂)。使用者可在到期前隨時把 `auto_renew` 改回 `true` 取消這個決定,恢復正常續訂。
> - **刪除帳號**(所有狀態皆可執行,包含 `trial`/`active`/`payment_failed`/`suspended`):不論目前處於哪個狀態、剩餘多少天數或試用額度,一律**立即**清空資料並將 `status` 轉為 `cancelled`,**不退款、不等到期**,視同使用者主動放棄剩餘權益。`active` 使用者可以不先取消訂閱就直接刪除帳號,行為與上述「取消訂閱後續用到期」互斥且優先——一旦執行刪除,直接跳過續用期,立即生效。

### 5. 500 字上限檢查邏輯

> ⚠️ **重要:此上限是帳號層級的全站加總,不是單一單字本的上限。** 使用者可以有多個單字本,500 字上限是這些單字本裡的單字數量「全部加起來」的總數,不是每個單字本各自可以存到 500 字。UI 上不論在哪個頁面顯示這條上限(首頁、單字本內、匯入預覽),數字來源都必須是 `users.word_count`,不能用單一單字本自己的字數去比對 500。

- 檢查時機:**新增/匯入單字送出時**一次性檢查(不逐字檢查),用「目前 word_count + 本次新增數量」是否超過 500 判斷
- 若超過:整批擋下或提示使用者「已達上限,僅能匯入至上限為止」
- word_count 於批次操作完成後,重新計算並寫入(非即時逐筆更新)

### 6. 通知機制

- **登入時提醒**:一律顯示,不論有無 email。依 `status` 顯示對應 banner:
  - `trial` 快到期 → 顯示剩餘天數
  - `payment_failed` → 顯示寬限期剩餘天數
  - `suspended`(在 3 個月保留期內)→ 顯示資料保留剩餘天數提醒,並顯示已凍結的連續天數與成就數(例:「你的 87 天連續紀錄與 12 個成就已暫停,付費後立即恢復」)
- **Email 提醒**:僅 `email IS NOT NULL` 時寄送,寄送前比對 `last_reminder_sent_at` 避免當月重複寄送
- **帳號設定頁文案**:需明確告知「填寫 Email 才能收到到期/扣款提醒通知信,未填寫僅能透過登入畫面查看提醒」

### 7. 暫停帳號資料保留

## 二、LINE Login 技術串接

> 沿用另一專案(AI 預約平台)已上線驗證過的架構,不使用 Supabase Auth,採手動 OAuth 流程。

### 1. LINE Developers Console 設定
- 建立 **LINE Login** channel(非 Messaging API channel)
- Callback URL:`https://你的網域/auth/callback`
- Scopes:僅勾選 `profile`、`openid`(**不需要 `email`**,email 由使用者自行於帳號設定頁填寫)
- 取得 `Channel ID`(LINE_CLIENT_ID)與 `Channel Secret`(LINE_CLIENT_SECRET)

### 2. 手動 OAuth 流程

```
1. 前端導向 LINE 授權頁(帶 client_id、redirect_uri、state)
2. LINE 導回 /auth/callback?code=xxx&state=xxx
3. 前端頁面驗證 state,呼叫後端 API
4. 後端 API:
   a. 用 code 換 LINE access token
   b. 用 access token 取得 LINE profile(userId、displayName、pictureUrl)
   c. UPSERT users 資料表(line_user_id 為唯一鍵)
   d. 寫入 httpOnly cookie(user_id)
   e. redirect 到主頁面
```

### 3. 首次登入建檔(範例邏輯)

```typescript
const { data: user } = await supabaseAdmin
  .from('users')
  .upsert(
    {
      line_user_id: lineProfile.userId,
      display_name: lineProfile.displayName,
      avatar_url: lineProfile.pictureUrl,
      // 僅在「新使用者」情況下需要設定以下三欄;若為既有使用者的重複登入,
      // upsert 不應覆蓋已存在的 status / trial_start_at / trial_end_at。
      // 實作上建議先查詢 line_user_id 是否已存在,不存在才帶入這三個欄位:
      status: 'trial',
      trial_start_at: new Date().toISOString(),
      trial_end_at: new Date(Date.now() + 30 * 24 * 60 * 60 * 1000).toISOString(),
    },
    { onConflict: 'line_user_id', ignoreDuplicates: false }
  )
  .select()
  .single()

response.cookies.set('user_id', user.id, {
  httpOnly: true,
  secure: true,
  sameSite: 'lax',
  maxAge: 60 * 60 * 24 * 30,
})
```

> ⚠️ 注意:`upsert` 若對既有使用者重複執行,不能每次都重設 `trial_start_at`/`status`,否則會讓老使用者的試用期被意外重新計算。實作時建議改用「先 `select` 判斷是否存在 → 不存在才 `insert` 帶入試用欄位 → 存在則只 `update` display_name/avatar_url」,而非單純依賴 `upsert` 一次帶入全部欄位。

### 3.1 `cancelled` 帳號再次登入的處理(定案)

- 資料清除完成、`status = cancelled` 後,`line_user_id` 這筆使用者資料列本身**不刪除**(僅清空其名下的 wordbooks/words/quiz 相關資料),保留作為登入識別之用
- 使用者日後用同一個 LINE 帳號再次登入時,**視為全新帳號**,重新給予 30 天試用期:
  - 判斷依據:查到 `line_user_id` 已存在但 `status = cancelled`
  - 處理方式:比照全新使用者,重設 `status = 'trial'`、`trial_start_at = now()`、`trial_end_at = now() + 30天`,並將 `word_count` 歸零;**`is_early_bird = false`(不可再次取得早鳥)**
  - **完整重置欄位清單**(避免舊帳號殘留資料影響新一輪試用期或誤觸發扣款排程):`is_early_bird = false`、`auto_renew = true`、`first_paid_at = NULL`、`next_billing_at = NULL`、`payment_failed_at = NULL`、`grace_period_end_at = NULL`、`suspended_at = NULL`、`data_purge_scheduled_at = NULL`、`last_reminder_sent_at = NULL`、`cancelled_at = NULL`、`current_streak = 0`、`longest_streak = 0`、`last_streak_date = NULL`、`streak_frozen_at = NULL`(使用者名下所有資料已於清除時一併刪除:`wordbooks`(連同 `words`、`word_tags`)、`tags`、`quiz_sessions`(連同 `quiz_answers`)、`word_stats`、`card_familiarity`、`word_progress`、`daily_tasks`、`user_achievements`、`user_language_settings`、`ai_extractions`、`game_scores`、`feedback`;由 `delete_account()` 明確刪除,因 `users` 資料列保留,外鍵 `ON DELETE CASCADE` 不會觸發。**新增帶 `user_id` 的資料表時,必須同步加入 `delete_account()`**)
- 首次登入建檔邏輯(見上方 3.)需擴充判斷條件:`line_user_id` 不存在 **或** 已存在但 `status = cancelled`,兩種情況都要重新帶入試用三欄位;僅當 `line_user_id` 存在且 `status` 非 `cancelled` 時,才只更新 `display_name`/`avatar_url`

### 4. 授權規則

- 不使用 RLS,所有資料存取走「API + service role」
- `SUPABASE_SERVICE_ROLE_KEY` 僅能在伺服器端使用,不可用 `NEXT_PUBLIC_*` 前綴
- 所有讀寫都需在 API 層驗證 `cookie.user_id === row.user_id`
- `REVOKE ALL ON TABLE ... FROM anon, authenticated`,避免繞過 API 直接用 anon key 存取
- **`cancelled` 狀態的 session 攔截**:若使用者刪除帳號或資料被清除排程處理時,前端仍持有尚未過期的 `user_id` cookie,後續任何 API 請求須在驗證階段檢查對應 `users.status`;若查到 `status = 'cancelled'`,一律回傳 401 並清除該 cookie,前端導向登入頁。使用者重新以 LINE 登入時,會依 3.1 節邏輯自動視為全新帳號、重置為 `trial`,不需要額外的「復活」流程

### 5. 設計原則

> v5:以下篩選邏輯僅適用於「自由練習」與卡牌模式。每日任務不使用手動篩選,範圍由系統依語言與熟練度產生(見第八節)。

- 標籤:使用者自訂、可多選、可跨單字本,用於複習/測驗時的複合篩選
- 篩選邏輯:**多選單字本時,單字本與單字本之間為聯集(OR)**——因每個單字只屬於一個 `wordbook_id`,若單字本之間也用 AND,篩選結果必為空集合。「單字本(聯集)」與「標籤」之間為交集(AND);**多選標籤時,標籤與標籤之間也是交集(AND)**——即同時選「動詞」+「易錯字」,篩選結果須同時具備這兩個標籤的單字,而非只符合其中之一。整體篩選邏輯為:`(單字本A 或 單字本B 或...) 且 (標籤A 且 標籤B 且...)`。前端與後端(SQL 查詢)皆須依此實作,避免出現邏輯誤解
- **空篩選條件的定義**:若 `filter_tag_ids` 為空陣列,略過標籤條件,僅依單字本篩選(不代表「篩選出沒有任何標籤的字」)。若 `filter_wordbook_ids` 為空陣列,視為尚未選擇範圍,**不允許開始測驗/背誦**,前端應擋下並提示使用者至少選擇一本單字本

### 4. 出題邏輯:錯誤率加權隨機(自由練習模式)

> 自由練習的單字本、標籤篩選**由使用者自行選擇**,系統不做「自動重測答錯單字」這類自動篩選功能。加權隨機只發生在「同一批篩選結果中,決定哪些字被抽到、抽到機率各是多少」這個層面。

1. 篩選出符合條件(單字本 + 標籤,皆由使用者手動選擇)的單字池
2. 計算池中每個單字的**抽選權重**:
   - 從未測驗過的單字(`attempt_count = 0`):給予最高權重(視同錯誤率 100%)
   - 已測驗過的單字:`weight = 1 + (1 - accuracy) × K`,`K` 為加權係數(建議先設為 4,之後可依實測調整),即錯誤率越高權重越高,錯誤率 0% 時權重最低(=1)
3. 使用「加權隨機抽樣、不放回」的方式,依權重抽出使用者設定的題數(推薦實作方式:Efraimidis-Spirakis 演算法——每個單字產生亂數 key = `random()^(1/weight)`,依 key 由大到小排序,取前 N 個)
4. 若使用者設定題數超過池子總數 → 全部單字入選,並提示實際題數較少
5. 加權隨機的設計意圖:讓錯誤率高的單字更常出現,藉此加強不熟單字的複習,但不是每次都固定只考錯的字,仍保留隨機性與正確率高的字偶爾出現的機會

### 5. 選擇題/是非題出題防呆

- 選擇題:單字池需至少 **4 個單字**(1 正確 + 3 干擾項),不足需提示使用者擴大篩選範圍或改選其他題型
- 是非題:單字池需至少 **2 個單字**(否則無法出「錯誤配對」)
- 檢查時機:使用者設定測驗條件、送出開始測驗前
- **依語言計算(2026/10/31)**:篩選範圍含多種語言時,某語言的字不足 4 個(選擇題)或 2 個(是非題),該語言的字不出題;所有語言都不足時提示原因,不允許開始

### 6. 是非題邏輯

- 出題時先隨機決定「本題問正確配對」或「本題問錯誤配對」(各半機率)
- 若為錯誤配對 → 該單字的 `answer` 換成同一單字池中、**與該題單字同語言**的另一個單字的 `answer`
- 使用者判斷「單字與中文配對是否正確」

### 7. 選擇題干擾項邏輯

- 正確答案:該單字本身的 `answer`
- 干擾項:從同一篩選後、**與該題單字同語言**的單字池中完全隨機抽取其他單字的 `answer`(MVP 不做相似度比對,先求功能可用)

### 8. 輸入題判定邏輯(純程式碼,不呼叫 API)

- **題目方向(2026/10/03 定案)**:題目顯示 `answer`(中文意思),使用者輸入外文 `term`。理由:使用者平時預設使用外語輸入法,填外文不需在中文與外語輸入法之間切換;反之若填中文,使用者的中文措辭常與 `answer` 譯義不完全相符,容易誤判。英、日、韓皆同
- **判定標準:與 `term` 或 `reading`(若有填)任一個完全一致即正確**;比對前統一 NFKC(全形/半形)、去除頭尾空白、忽略英文大小寫、片假名視同平假名。多字/少字/拼錯/順序錯皆判定 `is_correct = false`
- **日文讀音(2026/10/04 定案)**:漢字單字(如「受ける」)填了讀音「うける」後,輸入漢字寫法或假名讀音都算對,避免每次都要用輸入法選對漢字;未填讀音者只接受 `term` 的寫法
- 紅字標記時,以 `term` 與 `reading` 中和輸入較接近者作為 Levenshtein 比對對象;結果頁正確答案以兩層顯示(第一層 `term`,第二層為發音標註:英文音標、日文讀音、韓文羅馬拼音,見第十三節 3.)
- **紅字標記邏輯**(僅測驗結束後、結果頁一次顯示,不即時顯示,不存資料庫):
  - 使用 Levenshtein 對齊演算法找出「插入/刪除/替換」的具體位置
  - 替換錯誤(拼錯字母)→ 標記該字母為紅色
  - 少字母 → 標記缺少位置(底線或插入符號)
  - 多字母 → 標記多餘字母(紅色刪除線)
  - 若差異過大(完全不相關的答案)→ 不強行標紅,直接顯示正確答案

### 9. 例句題型(自由練習,2026/10/31)

> 句子題型只放在**自由練習**,作為可選題型;每日任務題型(第八節 5.)不變。理由:stage ≥ 4 的填空題是「已掌握」的判定關卡,考的是憑記憶拼出外文;句子題型屬辨認,不宜取代。

**題型**(`quiz_sessions.question_type` 新增值):

| 值 | 名稱 | 說明 |
|---|---|---|
| `example_choice` | 例句選擇 | 例句中 `example_target` 換成空格「＿＿」,從 4 個選項選出正確單字 |
| `example_tf` | 例句是非 | 判斷例句與中文翻譯是否相符 |
| `example_reorder` | 例句重組 | 看中文翻譯,把打散的詞塊排回原句 |

**出題範圍與防呆**

- 篩選規則同第三節 5.;**出題的字**限 `example` 不為 NULL 者(重組另需詞塊 3–12 塊)
- 干擾項來源為篩選後、**與該題單字同語言**的全部單字(不限有例句);是非題替換字同樣限同語言;整句播放使用該題單字的語言
- **同詞性優先**(2026/11/01):干擾項與是非題替換字先從與該題單字**同詞性**的字中隨機抽取,不足時再從其餘的字隨機補足。詞性取 `description` 的第一段(以「・」「、」逗號、斜線、分號或空白分隔,例如「名詞・約束」取「名詞」);該題單字沒有 `description` 時照舊全部隨機。理由:詞性不同時句子明顯不通,使用者不懂意思也能靠文法刪去
- 防呆依語言計算,規則同本節 5.;可出題(有例句)的字為 0 時提示「篩選範圍內沒有例句」
- 抽題沿用本節 4. 錯誤率加權

**例句選擇(`example_choice`)**

- 題目:挖空後的例句;作答中**不顯示**中文翻譯
- **選項一律顯示原形 `term`**(含正解),不顯示句中變化形,避免正解因形態不同而被一眼認出;選項依第十三節 3. 可附第二層
- 干擾項:從干擾項來源抽取(同詞性優先,見上),排除 `term` 正規化後與正解相同者
- 作答後:顯示完整例句(`example_target` 以粗體標示)、中文翻譯與對錯

**例句是非(`example_tf`)**

- 各半機率出「相符」或「不相符」
- 相符:顯示原例句 + 中文翻譯
- 不相符:將例句中的 `example_target` 替換為另一個字(同詞性優先,見上)的 `term`(原形,不做變化),中文翻譯不變;使用者判斷是否相符
- 作答後:顯示原例句(粗體標示)與對錯

**例句重組(`example_reorder`)**

- 題目:中文翻譯 + 打散的詞塊;可播放整句發音(第十一節發音,日文使用 `example_tts`);作答區上方提示「請依原句順序排列」(同第六節 5.)
- 點詞塊依序填入,點已填入的詞塊可退回;全部填入時判定一次,以詞塊文字序列與原句一致為正確(相同文字的詞塊可互換)
- 答錯不重作,顯示正確句子後進下一題

**學習紀錄**

- 寫入 `quiz_sessions`、`quiz_answers`;**不寫入 `word_stats`**(2026/11/01 起;`record_answers()` 對例句題型的作答帶 `skip_stats`,見本節 1.)。之前已寫入的成績不回溯清除
- **不影響 `word_progress`**(不升級也不降級):辨認型題目不足以證明記住拼寫,而重組答錯不一定是目標字的問題
- 不計入連續天數

## 六、卡牌背誦模式

### 1. `card_familiarity`(卡牌熟悉度自評)

| 欄位 | 型別 | 說明 |
|---|---|---|
| `word_id` | UUID FK | |
| `user_id` | UUID FK | 冗餘存,方便查詢 |
| `familiarity` | TEXT | `unknown`(不認得)/ `known`(認得) |
| `updated_at` | TIMESTAMPTZ | 最後標記時間 |

> 與 `word_stats`(測驗統計)完全獨立,互不影響彼此邏輯運算。卡牌模式的加權是二元的(認得/不認得各一個固定倍率),與測驗模式「依連續型錯誤率計算權重」是兩套獨立邏輯,不要合併實作。

### 2. 篩選邏輯
- 與自由練習共用同一套「單字本 + 標籤」篩選 UI(皆由使用者手動選擇)
- v5:卡牌模式屬自由練習性質,`card_familiarity` 與 `word_progress` 互相獨立,卡牌標記不影響熟練度、不計入連續天數
- 書寫練習(本節 4.)、重組練習(本節 5.)皆為卡牌模式的一種,上述規則同樣適用
- 篩選完成後可直接串接進入測驗(背完可馬上測)

### 3. 排序邏輯:加權隨機
- `familiarity = unknown` 或**尚未標記過**的單字 → 權重較高(如 3 倍機率),兩者權重相同
- `familiarity = known` → 權重較低(如 1 倍機率),但不完全排除,仍有機會出現
- 使用者可標記「認得 / 不認得」,寫入 `card_familiarity`

### 4. 書寫練習(2026/10/28)

> 透過「自己用輸入法打出單字」加深記憶。抄打本身記憶效果有限,真正的練習在於**隔一段時間後憑記憶打出來**(提取練習),因此抄寫與回想分成兩段,不在抄完後立刻回想同一個字。

**定位與入口**

- 屬卡牌背誦模式的一種玩法:背誦頁以切換鈕選擇「滑卡」或「書寫」,篩選條件(單字本 + 標籤)兩者共用(第三節 5.、本節 2.)
- 單字抽取沿用本節 3. 的熟悉度加權隨機
- 帳號狀態同背誦模式:`suspended` 不能使用

**不影響學習紀錄**

- 不寫入 `word_progress`、`word_stats`、`quiz_sessions` / `quiz_answers`,不計入連續天數,不觸發成就
- 回想結果寫入 `card_familiarity`:**每個字在本輪第一次回想**答對 → `known`;答錯或按「不會」→ `unknown`(重出時的作答不再改寫)
- 不新增資料表或欄位

**出題範圍**

- 一輪最多 **10 個字**;篩選結果少於 10 個時全部入選(至少 1 個即可開始)
- `term` 正規化後長度超過 **30 字元**的字不出題(長句抄打負擔過重);全部被排除時提示原因
- 同一輪不重複抽字

**第一段:抄寫**

1. 依序顯示每張卡:第一層 `term`、第二層發音標註(依第十三節 3. 與使用者設定)、`answer`、`description`;開啟自動播放時播放發音
2. 使用者在輸入框照著打出單字
3. 正規化後與 `term` 或 `reading`(若有)完全一致 → 立即判定通過,短暫顯示通過標示後進入下一張(約 0.5 秒)
4. 尚未一致時**不顯示錯誤**;使用者按 Enter(或點「確認」)才判定,不一致時以 Levenshtein 紅字標示差異(同第五節 8.),卡片內容持續顯示,使用者修改後可再確認
5. 「跳過」:不抄這張,直接下一張(此字仍會在第二段出題)
6. 全部抄完後顯示「開始回想」,按下進入第二段

**第二段:回想**

1. 本輪的字重新打散;若有 2 個以上的字,第一題不可是抄寫段最後一張(避免剛打完立刻回想)
2. 題目只顯示 `answer`(中文,完整譯義);**不顯示** `term`、`reading`、發音標註、`description`(描述可能含例句而洩漏拼法),作答中不提供發音按鈕
3. **輸入完成後按 Enter(或點「確認」)才核對**,輸入一致時不自動通過(2026/10/28 定案:避免韓文最後一個音節仍在組字、或片語打到一半時提前判定);比對規則同抄寫段(正規化比對,接受 `term` 或 `reading`)
4. **答對**:顯示 `term` 與第二層(依設定),開啟自動播放時播放發音,約 0.8 秒後下一題
5. **答錯**(Enter 確認且不一致):顯示紅字差異、正確 `term` 與第二層,使用者須**再抄一次**正確單字才能進下一題
6. **「不會」**:顯示正確 `term` 與第二層,使用者再抄一次後進下一題;視同答錯
7. 答錯或按「不會」的字,在本輪回想題目最後**再出一次**(最多再出 1 次,不再重複);再出時的對錯只顯示,不寫入 `card_familiarity`、不影響本輪成績

**結果畫面**

- 顯示本輪「第一次回想答對數 / 字數」與每個字的對錯(兩層顯示 `term`)
- 按鈕:「再練一輪」(以同一篩選條件重新抽字)、「回背誦」;每個畫面只有一個 `--stamp-red` 主要按鈕

**比對規則**

- 與填空題相同(第五節 8.):NFKC、去除頭尾空白、忽略英文大小寫、片假名視同平假名;接受 `term` 或 `reading`
- 日文漢字字在抄寫段與回想段皆接受讀音,避免輸入法選字造成卡關

**輸入法與鍵盤**

- **組字中不判定**:日文選字前、韓文音節組字中,輸入框為中間狀態;以 `compositionstart` / `compositionend` 追蹤,只在組字結束後(或非組字狀態的 `input`)才比對「是否已一致」(僅抄寫段與答錯後的再抄;回想段作答一律按確認才核對)
- 組字中按下的 Enter(`isComposing` 為 true 或 `keyCode` 229)用於輸入法確認,不觸發判定
- 輸入框設定 `autocomplete="off"`、`autocorrect="off"`、`autocapitalize="off"`、`spellcheck="false"`,並依單字本語言設定 `lang`(`en` / `ja` / `ko`,僅作為輸入法提示)
- 全站播放發音快捷鍵 S 在輸入框取得焦點時停用(避免打字時誤觸發音)
- 每一題出現時輸入框自動取得焦點並清空

**樣式**

- 依附錄 A;輸入框使用 IBM Plex Mono(同填空題),通過與答對使用 `--good`,錯誤標示使用 `--stamp-red`
- 動畫須支援 `prefers-reduced-motion: reduce`

### 5. 重組練習(2026/10/31)

> 把單字放回句子裡學。結構同書寫練習(本節 4.):先跟著原句重組,整輪完成後再蓋住原句默組。

**定位與入口**

- 背誦頁切換鈕:「滑卡 / 書寫 / 重組」,篩選共用
- 抽字沿用本節 3. 熟悉度加權;`suspended` 不能使用
- 不寫入 `word_progress`、`word_stats`、`quiz_*`,不計入連續天數、不觸發成就
- 每個字**本輪第一次默組**的結果寫入 `card_familiarity`(答對 `known`,答錯或「不會」`unknown`),規則同書寫練習

**出題範圍**

- 限 `example` 不為 NULL 且詞塊 3–12 塊的字;一輪最多 **10 句**;不足時全部入選(至少 1 句)
- 範圍內沒有可用例句時提示原因,並引導至單字本「AI 補例句」

**詞塊顯示**

- 詞塊打散後排列;若剛好依原順序排出,重新打散(最多 20 次)
- 作答區上方固定顯示「請依原句順序排列」(2026/11/01):判定只接受原句順序,日文、韓文語序較自由,英文副詞位置也常可移動,先講清楚規則以減少挫折;判定規則不變
- 日文含漢字的詞塊在上方顯示 `reading`(假名),跟隨「顯示假名讀音」設定(第十三節 3.);英文、韓文詞塊不顯示第二層

**第一段:跟組**

1. 顯示原例句(`example_target` 以粗體標示)、中文翻譯;開啟自動播放時播放整句發音,可手動重播
2. 點詞塊依序填入空格,點已填入的詞塊可退回;Backspace 退回最後一塊
3. 全部填入時判定:正確 → 通過標示,約 0.5 秒後下一句;錯誤 → 空格短暫標示錯誤,詞塊全部退回,重新排列
4. 「跳過」:直接下一句(此句仍會在第二段出題)
5. 全部完成後顯示「開始默組」

**第二段:默組**

1. 重新打散順序;2 句以上時第一題不可是跟組段最後一句
2. 題目顯示中文翻譯與播放按鈕(可重播,開啟自動播放時自動播放);**不顯示原例句**
3. **答對**:顯示完整例句(粗體標示目標字),約 0.8 秒後下一句
4. **答錯**:顯示正確例句,並以跟組方式(原句可見)再排一次才能繼續
5. **「不會」**:同答錯
6. 答錯或「不會」的句子在本輪最後再出 1 次;再出時的結果只顯示,不寫入 `card_familiarity`、不影響本輪成績

**結果畫面**

- 第一次默組答對數 / 句數,每句對錯;「再練一輪」、「回背誦」,只有一個 `--stamp-red` 主要按鈕

**其他**

- 動畫支援 `prefers-reduced-motion: reduce`;樣式依附錄 A,詞塊沿用拼字挑戰的方塊樣式

## 八、每日任務與熟練度(v5 新增)

> **定案**:學習範圍以系統依熟練度指派的「每日任務」為主要路徑。使用者只設定「學哪些語言」與「每日量」,不手動選範圍,目的是避免使用者習慣性只挑熟悉的範圍、遺漏真正還不熟的字;完成系統指派的任務本身也是成就感的來源。
>
> 手動篩選保留為「自由練習」(第五節)與卡牌模式(第六節),但**連續天數與每日任務相關成就只能透過每日任務取得**。
>
> 本節所有「日期」(今天、明天、到期日)一律以 **Asia/Taipei** 計算。

### 1. `user_language_settings`(使用者語言設定)

| 欄位 | 型別 | 說明 |
|---|---|---|
| `user_id` | UUID FK | |
| `language` | TEXT | `en` / `ja` / `ko` |
| `enabled` | BOOLEAN DEFAULT true | 是否產生該語言的每日任務 |
| `daily_review_limit` | INTEGER DEFAULT 30 | 每日複習字上限 |
| `daily_new_limit` | INTEGER DEFAULT 5 | 每日新字上限 |
| `peak_mastered_count` | INTEGER DEFAULT 0 | 該語言歷史最高「已掌握」字數,作為等級計算依據(見第九節 1.) |
| `extract_level` | TEXT (nullable) | 第二階段:AI 抽字的等級設定(英 CEFR / 日 JLPT / 韓 TOPIK),設定一次後每次抽取沿用(見第十節 1.) |
| `show_pronunciation` | BOOLEAN DEFAULT true | 2026/10/19 新增:是否顯示該語言單字的第二層標註(英文為音標、日文為讀音假名、韓文為羅馬拼音),各語言獨立(見第十三節 3.) |
| `updated_at` | TIMESTAMPTZ | |

> PK `(user_id, language)`。使用者建立某語言的第一本單字本時自動建立該語言設定(`enabled = true`)。

### 2. `word_progress`(熟練度與複習排程)

| 欄位 | 型別 | 說明 |
|---|---|---|
| `word_id` | UUID PK FK | 一對一對應 words |
| `user_id` | UUID FK | 冗餘存,方便查詢 |
| `stage` | INTEGER DEFAULT 0 | 熟練階段,0 = 尚未學習 |
| `due_date` | DATE (nullable) | 下次應複習的台北日期;`stage = 0` 時為 NULL |
| `introduced_at` | TIMESTAMPTZ (nullable) | 首次以新字身分學習的時間 |
| `last_reviewed_date` | DATE (nullable) | 最後一次「影響熟練度」的作答台北日期 |
| `lapse_count` | INTEGER DEFAULT 0 | 答錯降級次數 |
| `mastered_at` | TIMESTAMPTZ (nullable) | 達到「已掌握」的時間;降級後清為 NULL |

> 與 `word_stats`(正確率統計)、`card_familiarity`(卡牌自評)三者**完全獨立**:`word_stats` 照舊記錄作答的正確率供單字列表顯示(例句題型除外,見第五節 1.);`word_progress` 只負責排程與熟練度判定。新增單字時不必建立 row,無 row 視同 `stage = 0`。

### 3. 階段與間隔規則

| stage | 意義 | 答對後下次間隔 |
|---|---|---|
| 0 | 尚未學習 | — |
| 1 | 已學過(新字引入當天) | 1 天 |
| 2 | 複習中 | 3 天 |
| 3 | 複習中 | 7 天 |
| 4 | **已掌握** | 14 天 |
| 5 | 已掌握 | 30 天 |
| 6 | 已掌握 | 60 天 |
| 7(上限) | 已掌握 | 120 天 |

- **新字引入**:每日任務中首次學習的新字,作答後一律設為 `stage = 1`、`due_date = 明天`,不論答對或答錯(第一次見到的字,答錯是正常的)
- **答對**:若「今天 ≥ `due_date`」且今天尚未影響過熟練度 → `stage + 1`(上限 7),`due_date = 今天 + 新 stage 對應間隔`
- **答錯**:`stage` 降為 1、`due_date = 明天`、`lapse_count + 1`
- **「已掌握」定義**:`stage ≥ 4`,即在引入後於**三個不同日期**的到期複習中連續答對。達到時若 `mastered_at` 為 NULL 則寫入;答錯降級時清為 NULL(目前掌握數會下降,但已解鎖的成就與等級不收回,見第九節)
- **每日首次規則**:同一單字在同一台北日期,只有**第一次作答**會影響 `stage`(以 `last_reviewed_date` 判斷),之後作答只更新 `word_stats`,避免同日反覆刷題灌熟練度
- **自由練習對熟練度的影響**:答錯一樣降級(反映真實遺忘);答對只有在單字已到期時才升級,未到期提前答對不升級。**`stage = 0` 的單字在自由練習中作答不會被引入**(不論對錯,熟練度維持不變),新字一律由每日任務依建立順序引入,避免自由練習打亂新字佇列
- 由 `stage 4` 升到 `stage 4` 以上不會產生新的「已掌握」事件,僅更新間隔

### 4. `daily_tasks`(每日任務)

| 欄位 | 型別 | 說明 |
|---|---|---|
| `id` | UUID PK | |
| `user_id` | UUID FK | |
| `task_date` | DATE | 台北日期 |
| `language` | TEXT | `en` / `ja` / `ko` |
| `review_word_ids` | UUID[] | 今日複習字 |
| `new_word_ids` | UUID[] | 今日新字 |
| `completed_at` | TIMESTAMPTZ (nullable) | 全部作答完成時間 |
| `created_at` | TIMESTAMPTZ DEFAULT NOW() | |

> `UNIQUE (user_id, task_date, language)`。

**產生時機與規則**:

1. 使用者當日首次進入 App 時,為每個 `enabled = true` 的語言產生當日任務(lazy 產生,不需 cron);**當日產生後內容固定不變**,避免使用者重新整理刷出不同題目
2. 範圍:該使用者所有 `language` 相同的單字本中的全部單字
3. **複習字**:`due_date ≤ 今天` 的單字,依 `due_date` 升冪(最逾期優先),同日期依 `lapse_count` 降冪,取 `daily_review_limit` 個
4. **新字**:`stage = 0`(或無 row)的單字,依單字本 `created_at`、單字 `created_at` 升冪(照使用者建立的順序引入),取 `daily_new_limit` 個
5. **積壓保護**:若當日到期字數 > `daily_review_limit × 2`,當日新字數自動降為 0,避免複習量越滾越大把使用者壓垮
6. 超過上限的到期字不加入今日,自然保持逾期,隔日優先出題
7. 該語言單字總數 < 4 → 不產生任務,前端提示新增單字(選擇題干擾項不足)
8. 該語言既無到期字也無新字 → 不產生任務,前端顯示「今天沒有需要複習的字」並引導新增單字
9. `suspended` 狀態不產生任務

### 5. 任務出題方式

- **新字**:先顯示卡片(單字、答案、描述;有例句時一併顯示例句與翻譯,見第十三節 3.),使用者看完後出選擇題;卡片已揭示答案,此選擇題用意是確認是否記住,且新字不論對錯皆進入 stage 1(見本節 3.)
- **stage 1–3**:選擇題
- **stage ≥ 4**:填空題,看中文拼外文(判定見第五節 8.),英日韓皆同
- **題型於開啟任務時依單字當下的 stage 決定**(任務本身只固定單字清單,不固定題型):例如同一天先在自由練習答錯而降為 stage 1 的字,在每日任務中改出選擇題
- 干擾項從**同語言**的全部單字中隨機抽取
- 題目順序:複習字與新字隨機打散
- 作答紀錄寫入 `quiz_sessions`(`mode = daily_task`)與 `quiz_answers`,中途離開可在當日內續作

### 6. 完成判定

- 該任務所有單字都作答過 → 寫入 `completed_at`,觸發連續天數與成就檢查(第九節)
- 當日未完成的任務在隔日不延續;未作答的字仍保持到期,於隔日任務中優先出現
- **任務中的單字被刪除**(刪字或刪除整本單字本)時,載入任務與計算進度一律略過不存在的 `word_id`;剩餘單字全部作答完即判定完成。完成判定除了作答時檢查,進入 App 時也會檢查(**僅限 `task_date = 今天` 的任務**,不回溯補完過去日期的任務),以處理「最後幾個未答的字被刪除」的情況
- **任務中的單字已全部刪除**:該任務不算完成,也不重新產生,視同當日該語言沒有任務(適用第九節 2.「無任務可做的日子」);避免以「新增字、再刪除」的方式不作答就累積連續天數

- `peak_mastered_count` 於單字達到「已掌握」時檢查,目前掌握數超過即更新

### 2. 連續天數

- **計入條件**:當日完成**至少一個語言**的每日任務
  - `last_streak_date = 今天` → 不變
  - `last_streak_date = 昨天` → `current_streak + 1`
  - 其他 → `current_streak = 1`
  - 同步更新 `longest_streak`,並將 `last_streak_date` 設為今天
- **中斷判定**:使用者進入 App 時檢查,若 `last_streak_date < 昨天` 且 `streak_frozen_at IS NULL` → `current_streak = 0`
- **無任務可做的日子**:若當日所有已啟用語言都沒有產生任務(第八節 4. 第 8 點),視為保持:`last_streak_date` 設為今天但 `current_streak` 不加一,不會因為「沒字可複習」而斷掉

### 3. `user_achievements`(成就)

|---|---|---|
| `user_id` | UUID FK | |
| `achievement_key` | TEXT | 成就代碼 |
| `unlocked_at` | TIMESTAMPTZ DEFAULT NOW() | |

> PK `(user_id, achievement_key)`。成就定義(名稱、說明、圖示、門檻)寫在程式碼常數,不建資料表。**一經解鎖永不收回**。

第一階段成就清單:

- **檢查時機**:單字達到「已掌握」時、每日任務完成時
- 解鎖時前端顯示解鎖動畫或提示(沿用既有印章視覺風格)

### 4. 帳號狀態對成長資料的影響

> 對應營運文件第二節第 10 項:**「想保留已解鎖的成就」是持續付費的主要誘因**,因此暫停時凍結而非歸零。

| 狀態 | 成長資料處理 |
|---|---|
| `trial` / `active` | 正常運作 |
| `payment_failed`(寬限期) | 視同 active,正常運作,不凍結 |
| `suspended` | 成長面板**唯讀可見、呈凍結狀態**,顯示「付費後立即恢復」;不產生每日任務;進入暫停時寫入 `streak_frozen_at`,凍結期間不做中斷判定 |
| `suspended` → `active`(付費恢復) | 見下方「恢復處理」 |
| `cancelled`(刪除帳號或保留期滿清除) | `word_progress`、`daily_tasks`、`user_achievements`、`user_language_settings`、`ai_extractions`、`game_scores` 等使用者名下資料一併刪除(完整清單見第二節 3.1);`users` 的連續天數欄位依第二節 3.1 重置 |

**恢復處理**(由 `suspended` 轉回 `active` 時,於同一交易內執行):

1. 計算位移天數 `D = 恢復日(台北) − suspended_at 日期(台北)`
2. `last_streak_date = last_streak_date + D`(連續天數接續,不因暫停期間中斷)
3. 該使用者所有 `word_progress.due_date = due_date + D`(複習排程順延,避免恢復當天一次湧入大量逾期字)
4. `streak_frozen_at = NULL`

> 資料匯出(營運文件第七節)不包含成就與連續天數,僅匯出單字資料。

## 十、AI 抽字匯入(第二階段)

> **定案(2026/10/03)**:列為第二階段功能,第一階段不實作。定位為 Excel 匯入之外的**第二種匯入來源**,不取代 Excel 匯入。使用者貼上原文,系統以 AI 依使用者預先設定的等級抽出單字,產出 `term` / `answer` / `description` / `reading` 欄位,接續既有的匯入預覽與寫入流程(第四節)。

### 1. 等級設定

- 等級**依語言各自設定**,存於 `user_language_settings.extract_level`(見第八節 1.):

| 語言 | 等級制度 | 可選值 |
|---|---|---|
| `en` | CEFR | `A2` / `B1` / `B2` / `C1` |
| `ja` | JLPT | `N5` / `N4` / `N3` / `N2` / `N1` |
| `ko` | TOPIK | `1` / `2` / `3` / `4` / `5` / `6` |

- **只需設定一次**:首次使用該語言的 AI 抽字時,若 `extract_level` 為 NULL,先要求使用者設定;之後每次抽取直接沿用,抽字畫面**不再顯示等級選擇**
- 可於帳號設定頁修改,修改後自下一次抽取生效
- **等級語意(2026/10/27 修訂):抽出設定等級以及以下的單字,不往上**。例如英文 B2 → A2、B1、B2;日文 N3 → N5、N4、N3;韓文 TOPIK 3 級 → 1、2、3 級。比可選的最低等級(英 A2 / 日 N5 / 韓 1 級)更簡單的基本字不收。較簡單的字由使用者在預覽頁自行勾除;往上會混入過多難字,消耗學習熱情
- (原定案「只抽同等級、不往下也不往上」已於 2026/10/27 取消)

### 2. 流程

1. 使用者於某單字本內點「AI 抽字」,貼上原文;語言一律取該單字本的 `wordbooks.language`
2. 前端檢查:原文長度 ≤ 3,000 字元、本月剩餘次數 > 0、帳號非 `suspended`(後端須再次檢查);按下送出後立即鎖定按鈕,收到回應(成功或失敗)才解除,防止連點重複扣次
3. 後端 API 呼叫 OpenAI API(`OPENAI_MODEL` 指定的模型),以 JSON Schema 結構化輸出,要求**僅回傳 JSON 陣列** `[{term, answer, description, reading, level}]`,不含任何前言或 Markdown
4. 後端過濾:
   - 同一篇原文中重複的字只留一筆
   - 該使用者**同語言所有單字本**中已存在的 `term`(正規化比對:去除頭尾空白、忽略大小寫)
5. 進入預覽畫面(沿用 Excel 匯入步驟 2 的預覽 UI),顯示每個字的等級,依等級由難到易排序(同級維持 AI 回傳順序),使用者可勾除不要的字
5-1. 預覽畫面每個字顯示例句與翻譯(AI 造句標示「AI 例句」),可單獨「不保留例句」(該字照常匯入,例句欄位為 NULL)
6. 後續完全沿用第四節第 4–6 步(500 字上限檢查、寫入 `words`、更新 `users.word_count`)
7. 寫入後的單字即為 `stage = 0` 新字,依建立順序自然進入每日任務的新字佇列(第八節 4.),不需額外處理

- AI 回傳 0 個字時,提示「這段文字中沒有 {等級} 以下的新單字」

### 3. AI 抽取規則(prompt 須明確要求)

- **還原原形**:英文詞形變化(reimbursed → reimburse)、日文活用形(受けた → 受ける)、韓文活用形一律還原為辭書形
- **answer**:取該字**在原文脈絡中**的中文意思;若需多個譯義以頓號分隔,最多 3 個(填空題會將完整 `answer` 作為題目提示,譯義過多會讓提示冗長)
- **reading**:日文漢字詞的假名讀音(寫入讀音欄位,供填空題判定);其他語言為 null
- **description**:詞性;韓文漢字詞附對應漢字;**不放例句**(例句另存 `example`)
- **level**:AI 估計該字的等級,須為抽字範圍內的值;後端去掉 AI 可能加上的制度名稱(如「TOPIK 3」「3級」)後比對,範圍外標為 null 並排在最後。等級僅供預覽顯示,不寫入資料庫
- 排除專有名詞(人名、地名、品牌名)
- 等級判斷由 AI 估計,不另建官方等級字表;判斷誤差以預覽頁使用者自行刪字兜底
- **例句(2026/10/31)**:
  - **原句優先**:原文中有包含該字的**完整句子**時,逐字擷取該句(`example_source = 'original'`),不改寫;同一句可作為多個字的例句
  - **AI 造句**:原文只有單字清單、片段,或該句超過 150 字元時,改由 AI 依設定等級造一個簡短例句(`example_source = 'generated'`),意思須符合該字在原文中的用法;英文約 12 個字以內、日文與韓文約 40 字元以內,且詞塊不超過 12 塊(配合重組 3–12 塊);原句超過 12 塊時照常保留為例句,只是不用於重組
  - `example_translation`:例句的中文翻譯(繁體中文、台灣用語)
  - `example_target`:該字在例句中的實際形態(可能是變化形)
  - `example_chunks`:英文依空格切分,標點附在前一個詞塊,縮寫(don't)不拆;韓文依空格切分(語節);日文依文節切分(實詞 + 後接助詞、助動詞),句末標點附在最後一塊;日文含漢字的詞塊附 `reading`(假名)
  - `example_tts`:僅日文,整句假名,助詞「は」「へ」寫成「わ」「え」,詞塊間以半形空格分隔
- **伺服器端驗證**(不通過時依下列方式處理,單字本身照常匯入):
  - `example_target` 不是 `example` 的子字串 → 例句欄位全部為 NULL
  - 英文、韓文:詞塊以單一空格串接後須與 `example`(空白正規化後)一致,不一致時改由伺服器依空格重新切分
  - 日文:詞塊直接串接須與 `example` 一致,不一致時 `example_chunks` 為 NULL(例句保留,但不用於重組)
  - `example_tts` 含假名、長音、空格、標點以外的字元 → 為 NULL(改念原句)
  - 例句長度超過 200 字元 → 例句欄位全部為 NULL
- **例句簽章(防竄改)**:例句由 AI 產生後先送到前端預覽,確認寫入時才回傳伺服器;為確保例句欄位「一律由系統寫入」(第三節 2.),伺服器在預覽回應時以 HMAC-SHA256 對每個字的例句欄位簽章,寫入時重新計算比對:
  - 簽章範圍:AI 抽字綁定使用者 id、語言與 `term`;AI 補例句(8.)綁定使用者 id、單字 id 與 `term`。`term` 在預覽頁被修改後簽章即失效
  - 驗證不通過(內容被改動、簽章缺漏或格式不符)時丟棄該字的例句,單字本身照常寫入
  - 金鑰為伺服器端環境變數 `EXAMPLE_SIGNING_SECRET`(不可使用 `NEXT_PUBLIC_*` 前綴);未設定時不簽章、例句一律不寫入,AI 抽字其餘功能照常,伺服器 log 會留一行警告

### 6. 隱私與成本

- 原文處理完即捨棄,不寫入資料庫、不寫入應用程式 log;**唯一例外是例句**:原文中包含該單字的一句會作為 `example` 隨單字儲存(使用者可於預覽頁取消),原文其餘內容不儲存(2026/10/31)
- OpenAI 呼叫一律設定 `store: false`,不讓 OpenAI 儲存請求與回應;OpenAI 仍可能依其政策為濫用監控短期保留,且 API 資料不用於訓練模型
- 隱私權政策須補充「使用者貼上的原文會傳送給第三方 AI 服務處理」(營運文件第六節)
- 隱私權政策須載明「AI 抽字時,若原文含有該單字的完整句子,會保留該句作為例句並儲存於使用者帳號;原文其餘內容不儲存」,並更新生效日期(2026/10/31)
- 新增伺服器端環境變數 `OPENAI_API_KEY`、`OPENAI_MODEL`(不可使用 `NEXT_PUBLIC_*` 前綴);任一未設定時 AI 抽字回傳「尚未開放」
- 原文長度上限同時用於避免 Vercel function timeout 與 token 成本失控

### 7. 圖片轉文字(2026/10/18)

> 作為抽字的輸入輔助:圖片先轉成文字填入抽字文字框,使用者確認或刪改後,再走原本的抽字流程(2.)。不直接從圖片抽字,讓使用者能先刪掉不需要的段落。

- **流程**:抽字畫面的輸入階段點「上傳圖片」,一次選 1–2 張 → 前端逐張壓縮 → `POST /api/ai-transcribe`(multipart:`wordbook_id`、`image` 可重複 1–2 次)→ 同一次 AI 呼叫依選圖順序轉錄 → 回傳 `{ text, remaining, limit }` → 文字接在文字框既有內容之後(中間空一行)
- **限制**:一次最多 **2 張**(2026/10/27 由 1 張放寬),選超過 2 張時提示且不送出;前端縮到長邊 1,800px、轉 JPEG 後上傳;後端只接受 `image/jpeg` / `image/png` / `image/webp`,**合計**上限 4,000,000 位元組(Vercel request body 上限約 4.5MB)
- **HEIC**:由瀏覽器解碼後轉 JPEG(如 Safari);瀏覽器無法解碼時提示改用截圖或 JPG、PNG
- **模型**:沿用 `OPENAI_MODEL`(須支援圖片輸入),以 JSON Schema 結構化輸出 `{ text }`;prompt 要求照原文轉錄該單字本語言的文字,不翻譯、不修正、不說明,略過非該語言的文字
- **前置檢查**同抽字:帳號非 `suspended`、單字本屬於該使用者、該語言已設定 `extract_level`、本月剩餘次數 > 0
- **計次**:與抽字**共用每月次數**,AI 成功回傳即計 1 次(含沒有辨識到文字;1 張或 2 張都只計 1 次);錯誤或逾時不計次。寫入 `ai_extractions` 一筆 `kind = 'transcribe_image'`,`input_length` 為圖片合計位元組數
- 轉出的文字超過 3,000 字元時照樣填入,由使用者刪減到上限內才能抽字
- **隱私**:圖片不寫入資料庫、儲存空間或應用程式 log;隱私權政策須載明圖片會傳送給 OpenAI 處理

### 8. AI 補例句(2026/10/31)

> 為沒有例句的單字(手動新增、Excel 匯入、例句功能上線前的既有單字)產生例句。

- **入口**:單字本頁「AI 補例句」,對象為該單字本中 `example IS NULL` 的字,依單字 `created_at` 升冪,**一次最多 30 個字**
- **前置檢查**同抽字:帳號非 `suspended`、單字本屬於該使用者、該語言已設定 `extract_level`、本月剩餘次數 > 0
- **API**:送出單字的 `term` / `reading` / `answer`,AI 依 `extract_level` 造句(一律 `example_source = 'generated'`),產生欄位與驗證規則同本節 3.;例句意思須符合 `answer`
- **預覽**:列出產生的例句與翻譯,可勾除;確認後才寫入
- **計次**:AI 成功回傳即扣 1 次(同本節 4.),寫入 `ai_extractions` 一筆 `kind = 'generate_examples'`;錯誤或逾時不計次
- 不會覆蓋已有例句的字

## 十二、小遊戲(第二階段)

> **定案(2026/10/11)**:小遊戲是每日任務之外的額外樂趣,**不是學習主線**。三種遊戲:配對消除(已上線)、聽音辨字(2026/10/18 上線)、拼字挑戰(2026/10/26 改版上線)。

### 1. 共通規則

- **不影響學習紀錄**:遊戲作答不寫入 `word_progress`(熟練度)、`word_stats`(正確率)、`quiz_sessions` / `quiz_answers`,**不計入連續天數**,也不觸發每日任務相關成就;只記錄遊戲成績。理由:限時壓力下的誤按不應降級,刪去法猜中也不應升級;連續天數維持只能由每日任務取得(第八節),避免「玩一局」成為打卡捷徑
- **出題範圍只選語言**:系統從該語言 `stage ≥ 1` 的字隨機抽取;不足時以 `stage 0` 的字補足;該語言全部字數仍不足一局所需時不開放,並提示原因。每一局固定單一語言
- **帳號狀態**:`suspended` 不能開始新局,既有成績唯讀;`cancelled` 時成績一併刪除(第二節 3.1、第九節 4.)
- **動畫**:須支援 `prefers-reduced-motion: reduce`,蓋「新紀錄」章等動畫改為直接顯示最終狀態
- **入口**:導覽列「遊戲」→ `/app/games`(手機版收在選單內);每日任務完成畫面另放 ghost 樣式按鈕「玩一局配對」(紅色主要按鈕維持「回今日任務」),任務完成是最自然的獎勵時機

### 2. `game_scores`(遊戲成績)

| 欄位 | 型別 | 說明 |
|---|---|---|
| `id` | UUID PK | |
| `user_id` | UUID FK | |
| `game` | TEXT | `match` / `listen` / `spell` |
| `language` | TEXT | `en` / `ja` / `ko` |
| `word_count` | INTEGER | 配對:本局使用的字數;聽音、拼字:本局出題數 |
| `score` | INTEGER | 配對:完成毫秒數(含罰秒,越小越好);聽音、拼字:答對題數(越大越好) |
| `mistakes` | INTEGER | 錯誤次數 |
| `created_at` | TIMESTAMPTZ DEFAULT NOW() | |

- **個人最佳以同遊戲、同語言比較**(配對另需同 `word_count`)。聽音與拼字為「60 秒內答對幾題」,不同範圍與字量的難度不同,分數不宜直接跨語言比較;第三階段排行榜須沿用此比較條件
- 刷新個人最佳時蓋「新紀錄」章

### 3. 配對消除(`match`)

- **一局 6 個字 → 12 張牌,全部正面朝上**(看得到就配,非翻牌記憶遊戲),外文與中文混合打散排列
- 依序點兩張(外文與中文順序不限),配對正確即消除;配錯時兩張短暫標示錯誤並**加罰 3 秒**
- 從第一次點牌開始計時,12 張全部消除即結束;成績 = 經過時間 + 罰秒
- **中文只顯示第一個譯義**(`answer` 以頓號等分隔時取第一個),避免卡片過長
- **同一局排除意思重疊**:抽字時,第一個譯義正規化後相同的字不同時入選(例如兩本單字本都有「償還」),外文相同者亦同
- 外文牌可附讀音(日文有讀音時顯示於下方)
- **鍵盤操作**:12 張牌以鍵盤選取較繁瑣,**第一版暫不支援**,之後再評估(方向鍵移動 + Enter 選取)

### 4. 聽音辨字(`listen`,2026/10/18 上線)

- 播放發音(第十一節 Web Speech API),從 4 個選項選出聽到的字;60 秒內答對越多越好
- **選項**:4 選 1,只顯示外文;日文不附讀音
- **選項排除**:同一題的 4 個選項中,外文相同的字、日文讀音相同的字不同時出現(例:橋、箸皆為はし)。日文沒填讀音的字(如本身是假名的「はし」)以單字本身當讀音比對;比對前比照填空題正規化(NFKC、大小寫、片假名統一為平假名)
- **英文同音字不另外排除**(如 right / write):沒有字典無法判斷,同一題出現的機率也低,為刻意取捨
- **作答後**:顯示該字的中文意思與對錯,再自動進下一題
- **重播**:每題可重播,不限次數,計時照算
- **鍵盤**:數字鍵 1–4 作答、S 重播(與全站播放發音同一個鍵)
- **答錯**:不扣時間,只記錯誤次數(`mistakes`)
- **計分**:`score` = 60 秒內答對題數;`word_count` = 本局出題數(至少 1);個人最佳以同語言比較,不看 `word_count`(第 2 節)
- **出題**:題庫取該語言的字,學過的字(`stage ≥ 1`)在前、新字在後,各自打散後依序輪流當正解(上限 300 字);再玩一局時兩組各自重新打散
- **作答回饋**:顯示 1.2 秒後自動進下一題並播放,回饋期間計時照算
- **開始**:一定要有「開始」按鈕(iOS Safari 須使用者先點擊才允許語音播放),按下後開始計時並播放第一題
- **開放條件**:該語言至少 4 個字,且裝置有該語言的語音;不符合時在遊戲列表**顯示原因,不隱藏**
- **語音清單非同步載入**:iOS / Safari 等一開始可能回傳空清單,須等清單載入完成(或逾時)才判定「沒有語音、不開放」,避免誤判
- 其餘依共通規則(第 1 節):不影響熟練度、正確率、連續天數;`suspended` 不能開始新局;動畫支援 `prefers-reduced-motion`

### 5. 拼字挑戰(`spell`,2026/10/26 改版上線)

> 把單字本身的文字打散成方塊,混入 3 個不正確的文字(日文可能少於 3 個,見下),讓使用者把正確單字拼出來,藉由重組加深對拼寫的記憶。**不拆子母音**。

**方塊切分**:

| 語言 | 方塊單位 | 例 |
|---|---|---|
| `en` | 每個字母一塊 | apple → a / p / p / l / e |
| `ja` | `term` 的每個字元一塊(漢字、平假名、片假名、長音「ー」、疊字符號「々」、小字假名各自獨立),**不改用讀音** | 受ける → 受 / け / る |
| `ko` | 每個完整字(音節)一塊,不拆字母 | 학교 → 학 / 교 |

- 重複的字元各自一塊(apple 的兩個 p 是兩塊)
- 英文方塊保留 `term` 原本的大小寫

**出題範圍**(在共通規則之外再加條件):

- `term` 長度 2–12 個字元
- `term` 只能包含該語言的文字(英文字母;日文漢字、平假名、片假名、「ー」、「々」(2026/10/26 補充,如人々);韓文字),含空格、連字號、撇號、數字或其他符號的單字不出題
- 符合條件的字少於 5 個時不開放,並提示原因
- 同一局不重複出題,題庫用完才重新洗牌

**干擾方塊(3 塊;日文可能少於 3 塊)**:

- 干擾字元**不可出現在該 `term` 中**,確保只有一種正確拼法;比對以正規化後的字元為準(同第五節 8.:NFKC、忽略大小寫、片假名視同平假名),例:`Apple` 不可出現干擾字 `a`,含「カ」的字不可出現「か」(2026/10/26 補充)
- 優先從該使用者同語言其他單字的字元中隨機抽取,並優先選與 `term` 中字元**同類型**的字元(英文字母／平假名／片假名／漢字／韓文字),避免一眼就能排除
- 英文、韓文不足 3 個時以備用字元表補足:英文 a–z、韓文常用字表
- **日文不使用備用字元表**(2026/10/26 定案):同語言其他單字的字元不足 3 個時,有幾個算幾個(可能為 0 個),避免補上一眼就能排除的平假名
- 干擾字元彼此不重複(同樣以正規化後比對)
- 全部方塊(正確 + 干擾)隨機打散;若打散後正確字元恰好依原順序連續排列,重新打散

**作答流程**:

- 題目顯示 `answer`(中文,完整譯義);作答中不顯示 `term`、讀音、音標或羅馬拼音
- 上方顯示與 `term` 字數相同的空格;點方塊依序填入空格,點已填入的方塊可退回
- 空格全部填滿時自動判定,以正規化後與 `term` 完全一致為正確(比對規則同第五節 8.,但不接受 `reading`)
  - **答對**:顯示 `term` 與第二層發音標註(依第十三節 3. 與使用者設定),若開啟自動播放則播放發音,約 0.8 秒後進入下一題
  - **答錯**:空格短暫標示錯誤,`mistakes + 1`,方塊全部退回,同一題重新作答
- 「跳過」按鈕:顯示正確答案約 1 秒,`mistakes + 1`,進入下一題
- 一局 60 秒,從第一題出現開始計時;成績 = 答對題數,寫入 `game_scores`(`game = 'spell'`,`word_count` 為本局出題數)
- **鍵盤操作**:英文支援實體鍵盤,輸入字母即選取第一個相符且未使用的方塊,Backspace 退回最後一塊;日文、韓文因輸入法限制,第一版不支援鍵盤
- 答對時可使用印章元素(附錄 A),須支援 `prefers-reduced-motion`

**實作定案(2026/10/26)**:

- **開始按鈕**:進入頁面先顯示說明與「開始」按鈕,按下後才出第一題並開始 60 秒計時(仍符合「從第一題出現開始計時」)
- **計時**:答對顯示答案的 0.8 秒、跳過顯示答案的 1 秒,計時照算;答錯時空格標示錯誤 0.5 秒後方塊退回
- **跳過**:除正確 `term` 外,一併顯示第二層(依第十三節 3. 與使用者設定)
- **英文鍵盤**:不分大小寫(`term` 為 `Apple` 時按 `a` 可選到 `A` 方塊)
- **英文干擾字大小寫**:`term` 全大寫時用大寫,其餘用小寫
- **「ー」與「々」不當干擾字**:出現在 `term` 中時照常切成方塊,但不會被選為干擾字
- **同類型判斷**:`term` 混合多種文字時(如「受ける」含漢字與平假名),干擾字與其中任一類型相同即優先選用;同類型不足時再取同語言其他單字中的其他類型字元,最後才用備用表(日文不用)
- **韓文常用字表**:約 100 個常見音節,寫在程式內(`src/lib/spell.ts`)
- **打散**:剛好依原順序排出 `term` 時重新打散,最多重試 20 次(極短或全為相同字元的字無法避免時直接出題)
- **題庫**:可出題的字中,學過的字(`stage ≥ 1`)在前、新字在後,各自打散,上限 300 字
- **成績檢查**:`score` 上限 75 題(每題答對後至少停 0.8 秒),並檢查 `word_count ≥ score`、`word_count ≤ score + mistakes + 1`
- 遊戲列表依語言顯示可出題字數;少於 5 個時顯示原因,不顯示開始按鈕

## 十三、發音標註(2026/10/19,10/26 修訂)

> **定案**:單字以兩層顯示,第一層為 `term`,第二層為發音標註。英文與韓文的標註在存檔時自動產生、寫入 `words.pronunciation`,全部以開源字典或轉換規則產生,**不呼叫 AI、不計入 AI 抽字次數、不消耗 OpenAI 用量**。日文直接以 `reading` 作為第二層,不另外產生,也不自動補讀音。

### 1. 第二層內容

| 語言 | 第二層 | 來源 | 不顯示的情況 |
|---|---|---|---|
| `en` | IPA 音標(美式),以 `/…/` 包住 | CMUdict(ARPAbet 轉 IPA),寫入 `pronunciation` | 字典查不到 |
| `ja` | 讀音假名,照 `reading` 原樣顯示 | `words.reading`,不轉換、不另存 | `reading` 為空,或與 `term` 相同 |
| `ko` | 羅馬拼音(國語羅馬字) | 依規則轉換 `term`,寫入 `pronunciation` | `term` 不含韓文字 |

- **英文**:
  - 比對前去除頭尾空白並轉小寫;有多個發音時取第一個
  - **重音(2026/10/26 定案,第一版)**:依 CMUdict 重音數字轉換母音(如 AH0 → ə、AH1/AH2 → ʌ,ER0 → ɚ、ER1/ER2 → ɝ),**不標重音符號** ˈ ˌ(標示位置須先切音節,第一版不做)
  - 多字片語逐字查詢,全部查得到才以空格串接,否則為 NULL
  - CMUdict 隨伺服器端程式打包,不從外部下載、不送到前端
- **韓文**:盡量處理音變(如 같이 → gachi),以所用套件的能力為準,不另寫規則,也不提供手動修正
- **日文**:
  - **不自動產生讀音**。含漢字但未填 `reading` 的單字只顯示漢字
  - 單字列表與編輯畫面對這類單字顯示小提示「未填讀音」,引導使用者手動補上
  - 讀音可透過手動輸入、Excel 第 4 欄或 AI 抽字取得
  - 不顯示片假名對照與羅馬拼音

### 2. 產生時機(僅英文、韓文)

- **新增單字**(手動新增、Excel 匯入、AI 抽字匯入):在寫入 `words` 的同一個 API 請求內計算並寫入
- **編輯單字**:`term` 有變更時重新計算
- **既有單字**:上線時以一次性腳本補齊。腳本可重複執行,只處理所屬單字本 `language IN ('en','ko')` 且 `pronunciation IS NULL` 的單字
- **不允許手動修改**;Excel 匯入不新增此欄位,資料匯出則包含此欄位(唯讀參考)

### 3. 顯示規則

- **顯示位置**:單字列表、單字卡冊、背誦卡片(含書寫練習抄寫段)、每日任務卡片(新字卡片與選擇題的正反面)、測驗結果頁的正確答案,第二層顯示於 `term` 下方
- **測驗中**:
  - 選擇題、是非題可與 `term` 一起顯示;每日任務與自由練習皆顯示(2026/10/26)
  - **填空題**作答前不顯示,翻開答案後才顯示,因為第二層會洩漏拼法,而日文的讀音本身也算正確答案
- **書寫練習**(2026/10/28):
  - 抄寫段與 `term` 一起顯示第二層(依設定)
  - 回想段作答中不顯示,答對、答錯或按「不會」後才顯示(第六節 4.)
- **例句**(2026/10/31):
  - 單字本表格(每列加展開按鈕,例句與翻譯顯示於該列下方)、單字卡冊、背誦滑卡背面、每日任務新字卡片(2026/11/01;只顯示,不影響熟練度;有例句時卡片加高)顯示例句與翻譯;`example_source = 'generated'` 時標示「AI 例句」;例句旁有整句播放按鈕(日文有 `example_tts` 時念假名版,否則念原句)
  - 重組(背誦、自由練習)的日文詞塊上方顯示詞塊讀音,跟隨「顯示假名讀音」;英文、韓文詞塊不顯示第二層
- **小遊戲**:
  - 配對消除第一版不顯示英文音標與韓文羅馬拼音;日文讀音維持第十二節 3. 現行做法,並跟隨「顯示假名讀音」開關(2026/10/26)
  - 聽音辨字作答後以兩層顯示正解(英文音標、日文讀音、韓文羅馬拼音,依設定)(2026/10/26)
  - 拼字挑戰作答中不顯示,答對後才顯示(第十二節 5.)
- **個人設定**:
  - `show_pronunciation = false` 時,全站不顯示該語言的第二層,但英文、韓文資料照常產生
  - 設定頁依語言提供開關,文案為英文「顯示音標」、日文「顯示假名讀音」、韓文「顯示羅馬拼音」,預設開啟
  - 日文關閉時不影響填空題的讀音判定
- **樣式**:第二層使用 `--ink-soft`,字級比 `term` 小;英文與韓文用 IBM Plex Mono,日文假名用 Noto Sans TC

### 4. 帳號狀態

- 資料屬於 `words`,隨單字一併刪除,不需另外加入 `delete_account()`

### 5. 實作定案(2026/10/26)

- **套件**:英文 `cmu-pronouncing-dictionary` 3.0.0(ISC,約 13.5 萬字,第一次需要時才載入,只打包在伺服器端);韓文 `es-hangul` 2.4.0(MIT,依標準發音處理音變,如 신라 → silla、국물 → gungmul)
- **ARPAbet 轉 IPA**:r 音以 `r` 表示(學習字典慣用),不使用嚴格 IPA 的 `ɹ`;`g` 以 IPA 的 `ɡ` 表示
- **資料匯出**:Excel 第 5 欄「發音標註」、第 6 欄「例句」、第 7 欄「例句翻譯」(皆唯讀);前 4 欄維持與匯入相同,可原樣再匯入;例句不開放 Excel 匯入
- **補齊腳本**:`scripts/backfill-pronunciation.ts`,執行 `npm run backfill:pronunciation`(加 `-- --dry-run` 只計算不寫入);讀取 `.env.local`,以 id 遞增分批處理。2026/10/26 已於正式資料庫補齊 26 字(英 14、韓 12),無產生失敗
- **`get_language_words()`** 一併回傳 `pronunciation`(每日任務、單字卡冊、小遊戲使用)
- **「未填讀音」判斷**:日文 `term` 含漢字(Unicode Han)且 `reading` 為空

### 5. 元件

- **主要按鈕**:`--stamp-red` 底、白字、700;hover 轉 `--stamp-red-deep` 並上移 1–2px
- **次要按鈕**:`--ink` 底、白字
- **Ghost 按鈕**:`--white` 底、`--line` 邊框
- **文字連結型按鈕**:無底色,下方 1px 底線
- **Chip**:Mono 12px、`--white` 底;選中時 `--ink` 底白字
- **選取卡片**(如題型選擇):1.5px `--line` 邊框;選中時邊框變 `--stamp-red`
- **答題回饋**:答對使用 `--good`;答錯使用 `--stamp-red`;填空題 Levenshtein 比對的錯字以 `--stamp-red` 粗體加波浪底線標示,漏字以 `--stamp-red` 粗體標示
- **單字卡**:`--white` 底、`--line` 邊框、`--radius-lg`,term 用 Noto Serif TC 700,中文意思用 `--ink-soft`
- **印章元素**:朱紅圓形印章,靜止角度約 -14°,進場動畫為放大 1.5 倍旋轉落下(0.55s,`cubic-bezier(.2,.9,.3,1.2)`)。**建議用於成長回饋時刻**:完成每日任務、解鎖成就、單字升為「已掌握」
- **動畫**:所有動畫都必須支援 `prefers-reduced-motion: reduce`,該設定下改為直接顯示最終狀態
